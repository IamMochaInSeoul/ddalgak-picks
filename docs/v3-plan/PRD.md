> **버전:** v3.0-draft
> **작성일:** 2026-04-27
> **상태:** 기획 확정, 개발 착수 전
> **본 문서의 우선 적용 범위:** 신규 출시(v3.0 MVP)부터. 기존 v0.2.x 사용자에게는 마이그레이션 가이드 별도

## 1. Executive Summary

딸깍픽스는 **스튜디오에서 받은 1,000장 이상의 원본 사진을 폴더 구조 그대로 정리·셀렉해서 다시 스튜디오에 보내야 하는 고객**을 위한 AI 사진 셀렉터다. 가장 큰 시장은 **성장앨범**(만삭 → 베이비본 → 50일 → 100일 → 돌)으로, 시기별 폴더에서 각각 다른 장수를 골라야 하는 구조적 페인이 명확하다.

기존 시장의 셀렉 도구가 풀지 못한 두 가지 문제를 정조준한다:

1. **B급 오탐(誤探)** — "웃느라 눈이 감겨 보이는 컷"과 "인물 중심 아웃포커싱"을 B급으로 잘못 골라내, 사용자가 결국 다시 들여다봐야 하는 문제
2. **유사컷 피로** — 같은 포즈·복장·구도가 30~50장 연속되는 구간에서 "어떤 걸 골라야 하지" 하는 결정 피로

v3.0 MVP는 위 두 문제의 1차 필터링을 **사용자 개입 없이 완벽하게** 처리하고, **"일단 결제하고 써보자" 수준의 낮은 허들(₩4,900) + 무한 다운로드 패키지(₩15,000) + 비침해적 광고**로 매출을 시작한다.

핵심 KPI: 1차 셀렉 결과의 **사용자 수정률 < 12%**, **셀렉 정확도(F1 Score) ≥ 0.85**, 무료→유료 전환율 **10%**(허들 낮춤 효과), 월 활성 고객 **MAU 5,000** (출시 6개월 기준).

## 2. 비전 & 미션

### 비전
> **사진 셀렉이라는 노동을 한국 가정에서 영구 제거한다.**

### 미션 (3년)
1. 한국 성장앨범 셀렉 시장의 **사실상 표준 도구**가 된다
2. 스튜디오와 제휴해 **원본 전달 → 셀렉 → 회수**의 디지털 표준 워크플로우를 만든다
3. 셀렉 → 보정 → 인쇄/앨범 제작까지 이어지는 **One-stop 사진 라이프사이클 SaaS**로 확장한다

### 미션 (1년 — v3.0~v3.3)
1. "1,000장 → 30분 → 폴더별 셀렉 완료 → ZIP 회신" 플로우를 **사용자 결정 피로 없이** 완성
2. 무료 사용자가 결과 만족 후 **자연스럽게 유료로 전환**되는 워터마크/장수 제한 구조 정착
3. 광고 배너로 무료 사용자 운영비를 회수하는 **광고 슬롯 정책** 안착

## 3. 시장 정의 & 타겟

### 핵심 타겟 (Primary)

> **"스튜디오에서 1,000장 이상의 원본을 받아서, 폴더 구조를 유지한 채로 셀렉해서 다시 스튜디오에 보내야 하는 고객"**

이 정의는 두 가지 시장을 동시에 포괄한다:

| 시장 | 폴더 구조 예시 | 시기당 평균 원본 | 1회 셀렉 장수 | 연 발생 빈도 |
|------|----------------|------------------|-------------------|--------------|
| **성장앨범 (최우선)** | 만삭/, 베이비본/, 50일/, 100일/, 돌/ | 800~2,000장 | 10~50장/시기 | 시기별 1회 (총 5~7회) |
| **웨딩 본식·스냅** | 본식/, 원판/, 야외/, 신부대기실/ | 1,500~3,500장 | 50~150장 | 결혼 시 1회 |
| **펫 프로필** | 의상1/, 의상2/, 야외/ | 300~800장 | 20~80장 | 분기 1회 |
| **돌스냅 단발성** | 메인/, 가족컷/, 의상별/ | 500~1,200장 | 30~80장 | 1회 |

성장앨범 시장이 **빈도·결제 의향·재방문 가능성** 모두에서 압도적으로 높아, **MVP는 성장앨범에 100% 최적화**한다.

### 보조 타겟 (Secondary)
- 여행·일상 사진 중 S급만 추리고 싶은 일반 유저 (현재 Flow A 사용자)
- 반려동물 사진 셀렉 (Flow A 펫 모드)
- 향후: 스튜디오 자체(B2B SaaS) — v3.5+에서 검토

### 비대상 (Out of Scope)
- 전문 사진가의 작업 워크플로우 (Lightroom/Capture One 대체 의도 없음)
- 인쇄·앨범 제작 자체 (제휴 모델로만 접근)

## 4. JTBD (Jobs To Be Done)

### 메인 JTBD
> **"스튜디오에서 받은 폴더(만삭/베이비본/100일/돌)를 그대로, 각 폴더에서 내가 원하는 장수만큼 베스트만 뽑아서, 똑같은 폴더 구조로 ZIP 받기 — 평균 3~5시간 걸리던 작업을 30분 안에 끝내기."**

### 서브 JTBD (충족 우선순위 순)

1. **결정 피로 제거** — 비슷한 컷 30장 중 어떤 걸 골라야 할지 고민하지 않게 해줘
2. **오탐 안전망** — "웃겨서 눈 감긴 것처럼 보이는 좋은 컷"이 잘려나가지 않게 해줘
3. **시기별 비중 조절** — 만삭은 10장만, 돌은 50장 받고 싶어. 폴더마다 다르게
4. **주인공 우선** — 같은 컷 후보 중에서도 우리 아이가 잘 나온 게 우선이야
5. **수정 자유도** — AI가 고른 거 마음에 안 들면 내가 바로 바꿀 수 있어야
6. **비용 합리성** — 한 번 쓰는 사람도 부담 없이 시작하고, 만족하면 결제

### 안티 JTBD (의도적으로 안 하는 일)
- "내 사진을 너희 서버에 영구 저장해줘" → 프라이버시 우선, 원본 서버 업로드 최소화
- "AI가 내 취향을 학습해서 알아서 다 해줘" → 학습은 보조, 사용자 결정권 보장
- "내가 직접 보정해줘" → 보정은 v3.2+의 별도 단계, 셀렉과 분리

## 5. 페르소나

### 페르소나 1 — 지영 (33세, 워킹맘, 첫째 돌 준비) — **메인 타겟**

- **상황:** 스튜디오에서 만삭(800장), 베이비본(900장), 100일(1,200장), 돌(1,800장) 원본 USB로 받음. 각각 앨범에 들어갈 컷 골라서 회신해야 함
- **현재 행동:** 노트북에서 폴더 하나씩 열어 한 장씩 키보드 좌우 화살표로 넘기며 별표. 한 폴더당 1.5시간. 총 6시간 걸렸음
- **페인:**
  - 비슷한 포즈 30장 중 어떤 게 더 나은지 모르겠음 → 결정 피로
  - 눈 살짝 감긴 것 같은데 사실 웃어서 그런 것 같기도 → 망설임
  - 만삭에서는 10장만, 돌에서는 50장 골라야 하는데 그때그때 기준이 흔들림
- **목표:** 자기 전 1시간 안에 끝내기. 다음날 스튜디오에 ZIP 회신
- **결제 의향:** ₩4,900은 "일단 결제" 수준, 만족 후 ₩15,000 패키지로 업셀 자연스러움. 만족하면 둘째 때 다시 씀

### 페르소나 2 — 민호 (38세, 신혼, 본식 스냅 셀렉) — **세컨더리**

- **상황:** 결혼식 본식 스냅 작가에게 원본 2,800장 받음. 앨범사에서 80장 보내달라고 함
- **페인:** 비슷한 컷 너무 많음, 신부 표정이 좋은 것/신랑 표정이 좋은 것 동시에 챙겨야 함
- **결제 의향:** ₩4,900부터 시작, 본식 분량이 많아 ₩15,000 패키지 가능성 높음

### 페르소나 3 — 은수 (29세, 펫맘, 강아지 프로필) — **보조**

- **상황:** 펫 스튜디오에서 의상별 폴더 3개(300장씩) 받음. 인스타용으로 의상별 5~10장 고르고 싶음
- **결제 의향:** 무료가 좋고, 광고 배너는 괜찮음

### 페르소나 4 — 유리 (35세, 둘째 100일) — **재방문 케이스**

- **상황:** 첫째 때 딸깍픽스로 돌까지 다 했음. 둘째 100일에 다시 옴. **이전에 골랐던 첫째 100일 컷과 비슷한 톤·구도로 골라달라**는 요구 잠재
- **페인:** 형제 간 톤 통일, 과거 셀렉 이력 활용
- **결제 의향:** 구독(월 9,900원) 가능성 — 단, MVP에서는 중복 제거(IndexedDB 로컬)만 제공, 구독은 v3.3+

## 6. 사용자 시나리오

### 시나리오 A — 성장앨범 만삭 (메인 시나리오)

```
0분  랜딩 → "스튜디오용 셀렉" 카드 클릭
0:10 "셀렉용 폴더 있어요" 선택
0:20 만삭/, 베이비본/, 50일/, 100일/, 돌/ 5개 폴더 드래그앤드롭
0:30 자동 이벤트 태깅 결과 확인 (만삭=maternity, 돌=first_birthday 등)
0:40 폴더별 목표 장수 설정:
        만삭 10장 / 베이비본 15장 / 50일 20장 / 100일 30장 / 돌 50장
0:50 "유사컷 최대 허용 장수" 2장으로 설정
1:00 "분석 시작" → 예상 시간 표시 ("총 4,700장, 약 8분")
6:00 1차 인물 클러스터링 완료 → "인물 선택" 화면 자동 표시
        - 감지된 인물 4명 (대표 얼굴 썸네일 + 등장 횟수)
          예: "아이 (1,420컷)" "엄마 (890컷)" "아빠 (612컷)" "할머니 (210컷)"
        - 사용자가 "아이" + "엄마" 체크 → 모드는 OR(둘 중 하나라도 등장)
        - "아이만 등장한 컷"과 "엄마와 함께한 컷" 모두 후보로
6:30 분석 재개 (인물 가산점 적용) → 폴더별 본격 셀렉
8:00 분석 완료. 폴더 탭 UI에서 폴더별 결과 확인
        - 각 탭에 "선별 14장 / 제외 786장" 같은 배지
        - 각 컷의 좌상단에 등장 인물 칩 표시 (아이 / 엄마+아이 등)
        - 제외된 사진은 "제외 사유" 버킷별로 정리 (눈감음/흔들림/유사컷/주인공 미등장/...)
12:00 마음에 안 드는 1~2장만 토글, 나머지는 그대로
13:00 "ZIP 다운로드" 클릭 → 폴더 구조 유지된 ZIP 생성
14:00 워터마크 없는 원본 ZIP 받으려면 결제 → ₩4,900 카카오페이 원탭 (재추출 무한 + 다운 1회)
        또는 ₩15,000 패키지 선택 (재추출·다운 모두 무한, 90일 유효)
14:30 결제 완료, 워터마크 없는 ZIP 다운로드 시작
```

**총 소요: 15분 미만, 사용자 결정 6회 이내(인물 선택 1회 추가), 결제 1회. ₩4,900은 "고민 없이 결제" 가격대로 설정.**

### 시나리오 B — 무료 체험 후 결제 망설이는 케이스

```
사용자가 분석은 다 끝냈고, 갤러리에서 결과 확인까지 만족했음
결제 페이월 도달 → "무료로는 워터마크 ZIP만 가능, 50장까지"
사용자가 워터마크 ZIP을 일단 받아봄 → 워터마크 위치/크기 확인
"이 정도면 결제할 만하다" 확신 → 결제
```

**핵심 설계:** 워터마크는 **결과를 미리 다 보고도** 결제 결심이 서야 한다. 너무 거슬리면 이탈, 너무 안 거슬리면 결제 안 함. **§10.3 워터마크 정책** 참조.

### 시나리오 C — 광고만 보고 결제 안 하는 무료 사용자

```
펫 유저, 한 번만 쓰고 싶음
워터마크 ZIP 50장으로 인스타 업로드 → 워터마크는 잘려서 안 보임
무료로 만족, 결제 안 함, 광고 배너는 봤음
```

이 사용자도 **광고 노출 1회분의 가치**를 이미 만들었다. CPM 기준 손익 계산은 §11.4 참조.

## 6.B 토스식 직관 UX 원칙 (강제 사양)

> **사용자가 "어떤 버튼을 눌러야 하지?" 1초라도 고민하면 실패다.** 모든 화면은 다음 원칙을 강제 적용한다. PR 리뷰 시 이 원칙 위반은 머지 거부 사유.

### 6.B.1 화면 단위 원칙

| 원칙 | 구체 기준 | 위반 사례 |
|------|-----------|-----------|
| **한 화면 한 결정** | 메인 CTA 버튼 1개 (큼/볼드/색상 강조), 보조 액션 최대 1개(작고 회색) | "다운로드"와 "공유" 같은 크기로 나란히 배치 |
| **다음 액션은 시스템이 추천** | 화면 진입 즉시 베스트 옵션이 미리 선택되어 있어야 함 | 빈 폴더·빈 인물 카드 상태에서 사용자가 처음부터 선택해야 함 |
| **숫자는 결정 전에 공개** | 분석 시작 전 "약 7분 걸려요", 결제 전 "₩4,900", ZIP 전 "총 132장" | "분석 중..."만 표시, 시간 추정 없음 |
| **로딩은 스토리텔링** | 단계별 실수치 메시지("눈 감은 컷 17장 제외 중...") | "잠시만 기다려주세요" 단일 메시지 |
| **결제는 1탭** | 결제 화면 진입 시 카카오페이가 큰 기본 선택 | PG 4개 동등 나열, 사용자가 매번 고름 |
| **실수 복구 무한** | 모든 결정에 "되돌리기" 또는 "재추출" 명시 노출 | 한 번 토글한 사진 복원 불가 |

### 6.B.2 마이크로카피 5원칙 (한국어, 토스 톤)

1. **결과 약속을 먼저** — "10분 안에 셀렉이 끝나요" / NOT "사진을 선택해주세요"
2. **숫자로 안심** — "이미 1,247장이 분석 끝났어요" / NOT "분석 중입니다"
3. **다음 액션 단언** — "다음 단계로 →" / NOT "계속할까요?"
4. **에러는 해결책과 함께** — "사진을 다시 올려주세요. 손상된 파일이 있어요." / NOT "에러 발생"
5. **결제 직후 공감** — "결제 완료! 깨끗한 ZIP 만들고 있어요." / NOT "결제 처리되었습니다"

### 6.B.3 시각적 위계 4원칙

1. **메인 CTA는 화면 폭의 80%, 높이 56px+, 색상 강조** (랜딩의 "사진만 셀렉" / 분석의 "분석 시작" / 갤러리의 "ZIP 받기" / 결제의 "₩4,900 결제")
2. **보조 액션은 텍스트 링크 또는 작은 outline 버튼**
3. **결과 화면은 결정에 필요한 정보만** (장수 / 시간 / 인물 / 가격) — 탭 전환·메뉴 숨김
4. **광고는 결정 흐름 외곽에만** (§10.5)

### 6.B.4 인지 부하 측정

- 화면당 **사용자 결정 수 ≤ 1**
- 메인 CTA → 결과 도달까지 **클릭 ≤ 5회**
- 모든 화면 진입 → 첫 의미 있는 픽셀까지 **3초 이내**
- 새 사용자 첫 분석 완료까지 **사용 설명 0회** (직관으로만)

### 6.B.5 미리보기 + 복구 UX

- 결제 전 워터마크 ZIP을 갤러리에서 직접 미리 받아볼 수 있음 (§10.4)
- 결제 후에도 사용자 토글 + 재추출 무제한 (§10.3)
- 전체 분석 결과 폐기 후 새로 시작도 1클릭 ("처음부터 다시 시작" 버튼)

## 7. 핵심 차별점 7가지

> **이 7가지는 마케팅 카피·랜딩·앱 내 안내 어디서든 일관되게 노출한다.**

1. **폴더 구조 유지 셀렉** — 만삭/돌까지 통째로 받아서 통째로 돌려준다 (경쟁사 대부분 단일 폴더만 처리)
2. **시기별 장수 자유 설정** — 만삭 10장, 돌 50장 따로 정할 수 있음
3. **B급 오탐 안전망** — 웃어서 눈 감긴 컷·인물 중심 아웃포커싱은 절대 B급으로 안 본다 (`TECH_SPEC.md` §3 참조)
4. **유사컷 1차 정리 자동화** — 같은 포즈·복장·구도 N장 중 베스트만 자동 추출, 사용자 결정 피로 0
5. **주인공 인물 중심 셀렉** — 아이폰 사진앱 "인물" 탭처럼, 사진에 등장한 인물을 자동 클러스터링해서 주인공을 사용자가 직접 고를 수 있다. 표정·구도·카메라 응시 여부까지 반영해서 셀렉
6. **Google Drive 폴더 직접 연동** — 스튜디오가 Drive로 사진 보내면 PC 다운로드 없이 바로 분석. 썸네일만 받아 분석하고, 결제 후 선별된 사진만 원본 다운로드 (대역폭·시간 절감)
7. **100% 로컬 셀렉 + 선택적 서버** — 원본 사진은 결제·보정 시에만 서버 전송, 셀렉은 브라우저 내 처리 (인물 임베딩도 브라우저 내)

### 8.2 기능 카탈로그

#### F1 — 다중 폴더 업로드 [P0, 기존 계승]

- **아웃풋:** `FolderSession[]` (폴더당 1개)
- **계승:** 기존 `FolderUpload.tsx` 로직 재활용

#### F2 — 이벤트 태그 자동 추론 + 수동 변경 [P0, 기존 계승]
- **요구:** 폴더명 → EventTag 자동 매핑. 사용자가 드롭다운으로 변경 가능
- **태그 종류:** maternity / newborn / 50days / 100days / first_birthday / wedding / family / pet_profile / travel / other
- **계승:** 기존 `eventTagger.ts`

#### F3 — 폴더별 목표 장수 커스텀 [P0, 강화]
- **요구:** 폴더마다 다른 목표 장수 입력 가능
- **신규 사항 (v3.0):**
  - **이벤트 태그별 추천 장수 자동 제안** (만삭=10장, 돌=50장 등 통계 기반)
  - **"전체 합계" 실시간 표시** ("총 125장 선별 예정")
  - **앨범사 제출 규격 프리셋** (예: "○○스튜디오 돌앨범 50장 권장")

#### F4 — B급 사진 정밀 필터링 [P0, **본 버전의 핵심**]
- **요구:** 진짜 B급만 자동 제외, 사용자가 좋아할 수 있는 컷은 보존
- **상세 정의:** `TECH_SPEC.md` §3 (필수 참조)
- **핵심 보장:**
  - **웃어서 눈이 감긴 컷 ≠ 진짜 눈감음** — 입꼬리 각도·뺨 융기·EAR 시계열 패턴으로 구분
  - **인물 중심 아웃포커싱(배경 날아감) ≠ 흔들림** — 얼굴 영역 Laplacian만 검사, 배경은 무시
  - **저조도 노이즈 ≠ 흔들림** — 별도 분류
- **사용자 노출:** 제외 사유 표시 (눈감음/흔들림/유사컷/저품질/사용자 제외)

#### F5 — 유사컷 자동 그룹핑 + 베스트 추출 [P0, 강화]
- **요구:** 같은 포즈·복장·구도가 N장 연속될 때 베스트만 노출
- **신규 사항 (v3.0):**
  - 그룹 단위 시각화 (갤러리에서 "유사 5장 중 1장 선별" 배지)
  - 그룹 내 비교 모달 — 5장을 격자로 띄우고 사용자가 다른 컷 선택 가능
  - **"의상·배경 변화 감지"** — 의상이 바뀌면 자동으로 새 그룹 시작 (TECH_SPEC §3.4)

#### F6 — 분석 진행 스토리텔링 [P0, 신규]
- **요구:** 분석 중 "눈 감은 컷 17장 제외, 유사컷 142장 정리, 베스트 30장 선정 중..." 같은 실수치 단계별 노출
- **목적:** 결과에 대한 신뢰 + 대기 시간 체감 단축

#### F7 — 폴더별 탭 갤러리 + 제외 사유 분류 [P0, 강화]
- **요구:** 폴더 탭 UI, 각 탭에서 선별/제외/전체 3탭, 제외 탭은 사유별 버킷
- **계승:** 기존 `FolderGallery.tsx` + 강화

#### F18 — 인물 자동 클러스터링 + 주인공 선택 [P0, 신규]
- **요구:** 업로드된 모든 사진의 얼굴을 감지·임베딩해 동일 인물끼리 자동으로 묶고, 사용자가 주인공(1명 이상)을 선택해 그 인물 중심으로 셀렉
- **목표 정확도:** 인물 클러스터링 동일인 매칭 정확도 90% 이상 (성장앨범 기준, 같은 인물 외형 변화는 의상·헤어·표정 정도로 가정)
- **UX 흐름:**
  1. 분석 파이프라인 중간(얼굴 감지 직후)에 "인물 선택" 화면 자동 진입
  2. 감지된 인물별 대표 얼굴 카드 (썸네일 + 이름 미입력 시 "인물 1/2/3..." + 등장 횟수)
  3. 사용자가 인물 카드를 체크 (다중 선택 OK)
  4. "이 사람들 모두 등장(AND) / 한 명이라도 등장(OR)" 토글 — 디폴트는 **OR**
  5. 사용자가 이름을 직접 입력 가능(예: "지유", "엄마") — 다음 분석 세션에서 표시명 유지
  6. 인물 미선택 시 자동 디폴트: **등장 횟수 최다 1명을 자동 주인공**으로 (성장앨범 = 자연스럽게 아이)
- **점수 영향:**
  - 주인공 등장 사진: composition score 가산 (+15%)
  - 주인공이 사진 중심부에 위치: 추가 가산
  - 주인공이 카메라를 응시: 추가 가산 (응시 추정은 TECH_SPEC §3.8)
  - 주인공 미등장: composition score 감점 (-10%, BLOCK은 아님 — 가족 단체컷 등 보호)
  - AND 모드에서 일부 누락: 후보에서 제외
- **주인공 미등장 컷 보호 옵션:**
  - "주인공 없는 가족컷도 N장 보장" 토글 (폴더당 5장 디폴트)
  - 켜져 있으면 주인공 미등장 컷 중 베스트 N장은 별도 버킷으로 보존
- **프라이버시:** 얼굴 임베딩은 100% 브라우저 내 계산, 서버 전송 X. IndexedDB 24시간 후 자동 폐기
- **구현 명세:** `TECH_SPEC.md` §3.7 (인물 클러스터링), §3.8 (카메라 응시 추정), §3.9 (주인공 가산점 알고리즘)

#### F23 — Google Drive 폴더 연동 (업로드 소스 확장) [P0, 신규]

> **스튜디오가 USB 대신 Google Drive 공유 링크로 사진을 보내는 케이스가 늘고 있다. 매번 PC로 다운받아 다시 업로드하는 부담 없이 Drive 폴더를 직접 분석.**

##### F23.1 사용자 흐름

```
FolderUpload 화면
├── [기존] 컴퓨터 폴더 드래그앤드롭
└── [신규] "Google Drive에서 가져오기" 버튼
        │
        ├─ Google 계정 로그인 (이미 v0.2.x AlbumContainer에서 구현된 OAuth 재활용)
        ├─ Drive Picker 모달 → 폴더 선택 (다중 선택 가능)
        ├─ 선택된 폴더 트리 미리보기 ("만삭/(823장), 베이비본/(912장), 돌/(1,820장)")
        ├─ 이벤트 태그 자동 추론 + 폴더별 목표 장수 설정 (기존 동일)
        └─ "분석 시작" → 사진 다운로드 + 분석 동시 진행
```

##### F23.2 활용 케이스

- **스튜디오 → Drive 공유 → 고객:** 가장 흔한 케이스. 고객은 "내 드라이브에 추가" 후 본 도구에서 그 폴더 선택
- **카카오톡 사진첩 백업:** Drive에 자동 백업된 사진을 직접 분석
- **여러 기기 사이 동기화:** 스마트폰에서 찍은 사진이 Drive에 올라간 뒤 PC에서 분석

##### F23.3 다운로드 전략 (성능·비용 균형)

> **1,000장 원본 다운로드는 무겁다(평균 3GB+). 전략을 단계화해 사용자 체감 속도를 빠르게.**

| 단계 | 다운로드 대상 | 목적 |
|------|---------------|------|
| **분석 단계 (Stage 1~9)** | **썸네일만** (Drive API의 `thumbnailLink`, 400~800px) | 모든 분석은 썸네일로 충분 (얼굴 감지·pHash·임베딩) |
| **갤러리 표시** | 썸네일 (이미 받음) + 줌 모달은 더 큰 썸네일 | 사용자 확인용 |
| **무료 워터마크 ZIP** | 썸네일 + 워터마크 합성 | 결제 유도용이라 원본 화질 불필요 |
| **결제 후 클린 ZIP** | **선별된 사진만 원본 다운로드** (예: 132장만) | 1,000장 → 132장만 받으면 다운 시간 1/8 |

→ **결제 전까지 한 번도 원본을 다운받지 않음.** 결제 후 선별된 사진만 원본 다운 → ZIP 즉시 생성 → 다운로드.

##### F23.4 사용자가 체감할 속도

- **Drive 폴더 5개(약 4,700장) 선택 → 분석 완료 (썸네일만):** 약 9분 (썸네일 다운 추가 1~2분)
- **결제 후 선별 132장 원본 다운 → ZIP:** 약 2~3분
- 전체 시나리오 PC USB 시나리오 대비 추가 부담 약 3~5분

##### F23.5 Drive API 권한·범위

- **OAuth Scope:** `https://www.googleapis.com/auth/drive.readonly` (읽기 전용)
- **Picker로 선택된 폴더만 접근** — 사용자가 명시적으로 선택하지 않은 파일은 절대 접근 불가
- **토큰은 클라이언트 메모리만** (서버 전송 X, IndexedDB 저장 X)
- **세션 종료 시 토큰 폐기**, 재방문 시 재로그인

##### F23.6 환경변수 (기존 v0.2.x 재사용)

- `VITE_GOOGLE_CLIENT_ID` (기존)
- `VITE_GOOGLE_API_KEY` (기존)
- 추가 발급 불필요. 기존 AlbumContainer에서 사용 중인 키 그대로

##### F23.7 비활성·오프라인 폴백

- Google 로그인 실패 / 네트워크 단절 시 "컴퓨터 폴더 업로드"로 자연스러운 폴백
- "Drive에서 가져오기" 버튼 옆에 "또는 컴퓨터 폴더 드래그" 안내 항상 노출

##### F23.8 프라이버시 약속

- **사용자 Drive의 사진 메타·픽셀은 우리 서버로 절대 전송되지 않음**
- 분석은 100% 브라우저 내, ZIP 생성도 브라우저 내
- 결제 메타(이메일·주문번호)만 Supabase로 전송 (기존 §11.1과 동일)
- 개인정보처리방침에 "Google Drive 연동" 항목 명시 추가 필요 (출시 전 법무 검토)

##### F23.9 무료/유료 차별화 영향

| 항목 | 무료 | 유료 |
|------|------|------|
| Drive 폴더 선택 | ✅ 무제한 | ✅ 무제한 |
| 분석 (썸네일 기반) | ✅ | ✅ |
| 워터마크 ZIP (썸네일 합성) | ✅ 50장 제한 | — |
| **클린 ZIP (원본 다운로드)** | ❌ | ✅ |

> **결제 가치 강화:** 무료는 썸네일 워터마크 ZIP만 → 원본 화질의 클린 ZIP은 결제만 가능. Drive 시나리오에서 결제 동기 명확.

- **구현 명세:** `TECH_SPEC.md` §16 (Google Drive 연동 — OAuth/Picker/다운로드 파이프라인)

#### F22 — 다중 라벨러 협업 시스템 (Collaborative Labeling) [P0, 신규]

> **혼자 1,000장 라벨링하는 부담을 동료·가족·친구 N명에게 분산. 각자가 별도 라벨러 계정으로 작업하고, 합의 알고리즘으로 더 신뢰도 높은 정답지를 만든다.**

##### F22.1 라벨러 초대·접근

- **운영자가 어드민 페이지(F21)에서 라벨러 초대 링크 생성**
  - 초대 링크 1개당 1명 (재사용 X)
  - 라벨러는 이메일 + 닉네임 입력 후 가입 (Supabase Auth)
  - 24시간 유효, 미가입 시 만료
- **라벨러는 자신의 계정으로 로그인**해서 `/labeling` 접속
- **계정 분리 강제:** 같은 디바이스라도 다른 계정이면 별도 라벨링 데이터로 기록
- **운영자(어드민)도 라벨러 역할 가능** — 동시에 양쪽 작업

##### F22.2 라벨링 작업 분배

- **자동 분배 모드 (디폴트):** 1,000장을 라벨러 수로 나눔. 단, 합의 검증 위해 **각 사진은 최소 2명**이 라벨링
  - 예: 라벨러 5명, 1,000장 → 라벨러당 약 400장 (각 사진 2명 중복)
- **수동 분배 모드:** 운영자가 라벨러별 사진 묶음 직접 할당
- **남은 작업 자동 픽업:** 빠른 라벨러는 다른 사람의 미완성 사진을 추가 작업 가능 (선택)

##### F22.3 라벨링 UI (모든 라벨러 동일)

- **카드 한 장씩 표시 + 키보드 단축키:**
  - `1` = S급 (베스트)
  - `2` = A급 (애매)
  - `3` = B급 (빼야 함) — 누르면 사유 선택 팝업
  - `←/→` = 이전/다음 사진
  - `Space` = 건너뛰기 (잘 모르겠음, 다른 라벨러 의견 대기)
- **B급 사유 단축키:** `Q`(눈감음) `W`(흔들림) `E`(유사컷) `R`(기타)
- **자동 저장 5초 디바운스** (네트워크 끊겨도 IndexedDB에 임시 보관)
- **진행률 표시:** "본인 247/400 · 전체 1,180/2,000"
- **이전 라벨러 결정 비공개** (블라인드 라벨링 — 편향 방지)

##### F22.4 합의 알고리즘 (Consensus)

각 사진의 최종 정답 라벨 결정:

```
입력: 라벨러 N명의 라벨 (S/A/B + B 사유)

1. 다수결: N명 중 과반이 같은 라벨 → 채택
2. 동률 (예: S 1명, A 1명): "분쟁(disputed)" 마크 → 운영자 수동 검토 큐로
3. 한 명만 라벨 (1명만 작업) → 신뢰도 낮음 마크, 추가 라벨러 모집
4. B급 사유 동률: 가장 많이 선택된 사유 채택, 동률이면 alphabetical
```

- **합의 결과 = 최종 정답지** (정확도 게이트 §14.0 측정에 사용)
- **분쟁 사진**은 어드민 페이지에 표시되어 운영자가 1클릭 결정

##### F22.5 라벨러 통계·인센티브

- **라벨러별 진행률·완료수 어드민 대시보드 표시**
- **합의율(consensus rate):** 다른 라벨러와 일치한 비율 — 신뢰도 지표
  - 60% 미만 = "이 라벨러 결정이 다른 사람들과 자주 다름" → 운영자가 가이드 보강 필요
- **인센티브 (선택):**
  - 모든 라벨러에게 패키지(₩15,000) 무료 쿠폰 자동 발급 (F21.4 일괄 발급 활용)
  - 베타 출시 후 "초기 라벨링 기여자" 크레딧 표시 (앱 About 페이지)

##### F22.6 라벨링 데이터 모델

```
labelers: 라벨러 계정 (Supabase Auth users)
labeling_assignments: 라벨러 × 사진 매핑 (누가 무슨 사진을 작업할지)
labels: 개별 라벨 결과 (라벨러 N명 × 사진 = N개 row)
consensus_labels: 합의 알고리즘 결과 (사진당 1개 row, 최종 정답지)
```

##### F22.7 프라이버시

- 검증셋 사진은 운영자가 미리 익명화 처리 (얼굴 모자이크는 X — 검증 의미 없어짐 / 단, 라벨러는 NDA 동의 후 작업)
- 라벨링 도구는 라벨러 인증 후에만 접근 (Supabase RLS)
- 라벨러는 라벨링 결과만 보낼 수 있고, 사진을 다운로드할 수 없음 (DRM 워터마크 + 우클릭 차단 + DevTools 보호)

- **구현 명세:** `TECH_SPEC.md` §14.0.5 (라벨링 협업 시스템) + §15.3 (어드민 라벨링 관리)

##### F21.3 계정·권한 관리 (Account Management)

> **사이트 운영에 필요한 모든 계정·역할을 한 곳에서 관리.**

**계정 종류 (역할 기반):**

| 역할 | 권한 | 접근 경로 | 가입 방식 |
|------|------|-----------|-----------|
| **admin** | 모든 권한 — 결제·쿠폰·라벨러·콘텐츠·비상 토글 | `/admin/*` 전체 | ENV의 ADMIN_PASSWORD_HASH로 단일 어드민 (MVP) → v3.2에서 다계정 |
| **labeler** | 자신의 라벨링만 read/write, 검증셋 사진 view (signed URL) | `/labeling` | 어드민이 발급한 초대 링크로 가입 (F22) |
| **member** (v3.2+) | 자신의 결제·분석 이력 read | `/account` | 카카오/구글 소셜 로그인 |
| **guest** (MVP 디폴트) | 분석·결제 (비회원, 이메일만) | 메인 사이트 | 가입 X, 결제 시 이메일만 |

**MVP 시점 운영자 화면:**
- **모든 계정 목록** (어드민 + 라벨러, 추후 회원 자동 합류)
- 계정별: 이메일 / 닉네임 / 역할 / 가입일 / 마지막 활동 / 라벨링 통계 (라벨러)
- **역할 변경:** 라벨러 → 어드민 승급 / 비활성화 / 강퇴 (1클릭)
- **비밀번호 재설정 링크 발송** (라벨러 분실 시)
- **활동 로그:** 계정별 최근 100개 액션 (라벨링·결제·어드민 변경 등)
- **일괄 액션:** 비활성 라벨러 전체 정리, 라벨링 완료 라벨러에게 보상 쿠폰 일괄 발급

**MVP 비회원 결제 흐름과의 연결:**
- 게스트 결제 시 이메일만 받음 → `email_directory` 테이블에 자동 기록
- 같은 이메일로 회원 가입(v3.2) 시 기존 결제 이력 자동 병합
- 어드민 페이지에서 **이메일 단위로 모든 활동 추적** 가능 (분석 세션·결제·환불·문의)

##### F21.5 오류·정확도 모니터링

#### F19 — 갤러리 파일명 가림 (Anonymized Display) [P0, 신규]
- **요구:** 갤러리·인물 선택·줌 모달 등 모든 화면에서 **사진의 원본 파일명을 표시하지 않는다**. 대신 일관된 가명(예: `DDP-만삭-001`, `DDP-100일-042`)을 보여준다.
- **목적:** 사용자가 "AI가 골라준 베스트 컷의 파일명"만 따로 적어 PC 원본 폴더에서 수동 셀렉하는 우회를 방지. 서비스 가치 = 셀렉 결과물 자체가 되도록 강제.
- **표시 규칙:**
  - 가명 형식: `DDP-{이벤트태그한국어}-{3자리 zero-padded 인덱스}`
    - 예: `DDP-만삭-001`, `DDP-돌-042`
  - 원본 파일명·EXIF 촬영시각·경로 모두 UI에 노출 금지
  - 마우스 호버·우클릭·개발자도구 가능한 한 차단 (완전 차단은 어려움, "성실한 어그러뜨림" 정도)
- **ZIP 다운로드 시:**
  - **원본 파일명 그대로 보존** (스튜디오 매칭 편의)
  - 파일명 가림은 **클라이언트 UI에서만** 적용
- **무료 사용자 워터마크 ZIP:**
  - 워터마크 ZIP의 파일명은 **가명 사용** (`DDP-만삭-001.jpg` 식)
  - 무료 사용자가 가명만으로는 원본 파일을 역추적 불가 → 결제 동기 강화
- **결제 사용자 클린 ZIP:**
  - 원본 파일명 보존
- **개발자 도구·소스 보호:**
  - 갤러리 썸네일에 `data-original-name` 같은 속성 부착 금지
  - DevTools에서 PhotoEntry 객체 직렬화 시 원본 파일명 마스킹 헬퍼 적용 (Sentry 로그도 마스킹)

## 10. 수익 모델

### 10.1 핵심 전략 — "결제 허들 최소화"

> **사용자가 "결제할까 말까" 망설이는 순간이 가장 큰 이탈 지점이다. ₩4,900은 한 번의 결심 없이 "일단 한 번 해보자" 결정을 만든다.**

이 전략의 의도:
- **고전환·저단가**가 **저전환·고단가**보다 누적 매출 + 바이럴이 더 크다
- 일단 결제 경험한 사용자는 다음 시기(둘째 100일/돌)에 ₩15,000 패키지로 업셀 자연스러움
- 결제 후 결과에 만족 못 하면 "안 좋은 바이럴"이 광범위해질 수 있어 (§14 위험요소) — **결과 정확도가 가격보다 중요**

### 10.2 수익원 구성

| 수익원 | 비중(예상) | 도입 시점 |
|--------|-----------|-----------|
| 1회 결제 (₩4,900) | 55% | MVP |
| 패키지 결제 (₩15,000) | 30% | MVP |
| 광고 배너 (모든 사용자, 비침해 디자인) | 10% | MVP |
| AI 보정 인앱 결제 | 5% | v3.2+ |
| 구독 / B2B / 제휴 | - | v3.5+ |

### 10.3 무료 vs 유료 경계 (MVP 기준)

| 구분 | 무료 | 1회권 ₩4,900 | 패키지 ₩15,000 |
|------|------|---------------|------------------|
| 분석 | ✅ 무제한 | ✅ 무제한 | ✅ 무제한 |
| 폴더 수 | ✅ 무제한 | ✅ 무제한 | ✅ 무제한 |
| 갤러리 결과 보기 | ✅ | ✅ | ✅ |
| 제외 사유 보기 | ✅ | ✅ | ✅ |
| **재추출 (사용자 토글 후 재선별)** | ✅ 무제한 | ✅ 무제한 | ✅ 무제한 |
| **워터마크 없는 ZIP 다운로드** | ❌ | ✅ **1회만** | ✅ **무제한** |
| **워터마크 ZIP (50장 제한)** | ✅ | — | — |
| 앨범 배치 ZIP | ⚠️ 워터마크 | ✅ (1회) | ✅ 무제한 |
| 광고 배너 | ⚠️ 비침해 노출 | ⚠️ 비침해 노출 (작게 유지) | ✅ 비노출 |
| 유효기간 | — | 24시간 (다운 후 만료) | **90일** |

> **중요:** 1회권을 결제했더라도, 결과가 마음에 안 들면 사용자 토글 + 재추출은 무제한이다. **다운로드만 1회 제한.** 이 차이가 "결제 후 후회 없음"을 보장하고, "일단 결제하고 써보자" 심리적 안전망이 된다.

### 10.4 워터마크 정책

- **위치:** 사진 우측 하단, 가로 폭의 15% 크기
- **내용:** "딸깍픽스" 로고 + 반투명(opacity 40%)
- **디자인 원칙:** SNS 업로드 시 잘려나가지 않게 적당히 안쪽, 그러나 인쇄/앨범 제출용으로는 명확히 거슬림
- **검증 방법:** 실제 앨범사 5곳에 워터마크 ZIP 보내서 "이 정도면 받아주는가" 사전 테스트

### 10.5 광고 정책 — "모든 화면, 단 거슬리지 않게"

> **원칙:** 분석 결과·결제 의사결정·다운로드 흐름을 절대 방해하지 않는다. 사용자가 광고가 있다는 사실을 의식하지 않을 정도로 자연스러워야 한다.

#### 노출 위치 (모든 단계, 단 비침해 디자인)

| 화면 | 위치 | 크기 | 특이사항 |
|------|------|------|----------|
| 랜딩 | 푸터 위 | 728×90 | 1차 인상에 광고 인지 X |
| 업로드 | 상단 미니배너 | 728×90 | 드래그앤드롭 영역과 충분히 분리 |
| 분석 대기 | 진행률 바 아래 | 728×90 | 가장 자연스러운 슬롯 (5~8분 노출) |
| 인물 선택 | 인물 카드 그리드 외곽 | 사이드 200×600 | 인물 카드와 시각적 분리 |
| 갤러리 | 갤러리 그리드와 ZIP 버튼 사이 띠 | 728×90 | 결정 흐름 위 X, 아래 O |
| 페이월 직전 | **광고 없음** | — | 결제 의사결정 보호 |
| 결제 결과 | 영수증 하단 카드 | 300×250 | "다음 시기에도..." 자연스럽게 |

#### 비침해 디자인 5원칙

1. **분석 결과·인물 카드·결제 버튼 위에 절대 X**
2. **전면 인터스티셜·자동 재생·자동 사운드 절대 X**
3. **AdSense 표준 단위만**, 자동 광고(Auto Ads) 사용 금지
4. **광고 영역에 회색 톤 외곽선** + "광고" 라벨 항상 노출 (사용자가 광고임을 즉시 인지하면 거슬림 → 익숙함으로 전환됨)
5. **패키지 결제 사용자는 즉시 비노출** (1회권은 작게 유지하되 노출 — 다음 결제 유도)

#### 광고 매출 시뮬레이션 (재추정)

```
무료 사용자 MAU 4,000명 + 1회권 사용자 800명 = 광고 노출 4,800명
1인 평균 광고 노출: 12회 (모든 화면 통과 시)
월 노출 = 4,800 × 12 = 57,600회
한국 AdSense 평균 CPM ₩2,500
월 광고 매출 = 57,600 / 1000 × 2,500 = ₩144,000
```

광고는 **운영비 일부 충당** 수준. 매출 엔진은 결제.

## 11. 가격 정책

### 11.1 결제 상품 (MVP)

| 상품명 | 가격 | 내용 | 유효기간 |
|--------|------|------|----------|
| **딸깍픽스 1회권** | **₩4,900** | 현재 분석 세션 워터마크 해제 + **클린 ZIP 다운로드 1회** + 재추출·수정 무제한 | 결제 후 24시간 (다운 시점부터 24시간 카운트) |
| **딸깍픽스 패키지** | **₩15,000** | **모든 분석 세션 워터마크 해제 + 클린 ZIP 다운로드 무제한** + 재추출·수정 무제한 + 광고 비노출 | **90일** |

> **가격 정책은 출시 후 데이터에 따라 조정 가능.** §12 KPI 기반으로 ±30% 범위 내 A/B 테스트 진행.

### 11.2 가격 결정 근거

- **₩4,900 = "고민 없이 결제" 가격대** — 카페 음료 1잔 가격, 결제 망설이지 않는 임계값
- **₩15,000 = "어차피 한 번에 끝낼 거면" 패키지** — 1회권 3.06배 가격으로 무제한 + 90일. 성장앨범 만삭~돌 1년 커버
- **앨범 1권 평균가:** 30~50만원 → 셀렉 보조 도구 ₩4,900은 **편익 대비 1/100 수준**, 결제 저항 매우 낮음
- **국내 유사 사진 도구:** 무료 위주, 일부 ₩5,000~₩15,000 1회권 → ₩4,900은 시장 최저가권
- **사용자 인지 가격(perceived price):** "커피 1잔 값으로 6시간 노동 단축" 메시징

### 11.3 패키지 설계 의도

성장앨범은 만삭~돌까지 5~7회 발생. **첫 번째 ₩4,900 결제 후 만족 → 다음 시기 결제 시점에 ₩15,000 패키지 노출 → 자연스러운 업셀.** 패키지 사용자는 광고도 보지 않으므로 가장 깨끗한 사용자 경험. 90일은 100일~돌 사이 평균 간격을 충분히 커버.

### 11.4 결제 후 후회 방지 장치

> **사용자가 결제하고도 결과 마음에 안 들면 환불 부담이 커진다. 결제 전후의 안심 장치를 설계.**

- **결제 전 미리보기:** 워터마크 ZIP을 먼저 받아볼 수 있어 결과 품질을 확인 후 결제 (시나리오 B)
- **결제 후 재추출 무제한:** 사용자가 토글·인물 변경·재선별을 무제한 시도해도 결제 효력 유지
- **다운로드 24시간 유효:** 1회권도 24시간 내라면 같은 결과 ZIP 재다운 가능 (네트워크 사고 대응)
- **명확한 환불 정책:** 다운 0회 시 자동 환불, 다운 1회 후 분쟁 시 운영자 수동 처리

### 11.5 결제 PG (확정 — 2026-04-27)

- **포트원(PortOne) V2 통합 게이트웨이** — 카카오페이/토스페이/신용카드/네이버페이 모두 한 번의 가맹 등록으로 활성화

## 12. 성공 지표 (KPI)

### 12.1 노스 스타 메트릭

> **월간 유료 결제 건수 (Monthly Paid Sessions) × 셀렉 정확도(F1 Score)**

매출만 보면 정확도가 낮아도 단기 매출이 늘 수 있다. 하지만 부정 바이럴이 빠르게 누적되어 6개월 후 매출이 급락한다. **두 지표를 곱해 추적**한다.

### 12.2 정확도 지표 (최우선 — 모든 출시·업데이트의 게이트)

> **사용자가 "결제하고 받았더니 별로였다"는 후기를 만들지 않는 것이 가장 중요한 KPI다.**

| 지표 | 목표 | 측정 방법 | 게이트 |
|------|------|-----------|--------|
| **B급 사진 검출 정확도 (Recall)** | ≥ 92% | 사전 라벨링된 검증셋 1,000장에서 진짜 B급을 얼마나 빼냈는가 | **출시 게이트 — 미달 시 출시 보류** |
| **B급 사진 오탐률 (False Positive Rate)** | ≤ 8% | 사전 검증셋에서 좋은 컷을 잘못 빼낸 비율. **이 수치가 가장 중요** — 좋은 컷 손실은 부정 바이럴 직결 | **출시 게이트** |
| **셀렉 결과 F1 Score** | ≥ 0.85 | 정밀도와 재현율의 조화 평균 | 출시 게이트 |
| **인물 클러스터링 정확도** | 동일인 매칭 ≥ 90%, 다른 인물 분리 ≥ 95% | 사전 라벨링된 가족 이미지 200세트로 검증 | 출시 게이트 |
| **카메라 응시 추정 정확도** | ≥ 80% | 정면 응시 라벨 30장 vs 비응시 30장 검증 | 베타 게이트 |
| **1차 셀렉 결과의 사용자 수정률** | **< 12%** | 갤러리에서 토글한 비율 | 운영 모니터링 |

#### 검증 데이터셋 구축 (출시 전 필수)

> **개발자(Claude Code)가 수치만 맞추는 함수가 되지 않도록, 데이터셋 라벨링은 기획자가 직접 한다.**

- **B급 검증셋 1,000장:** 성장앨범 도메인 실제 사진 (만삭 200, 베이비본 200, 100일 200, 돌 200, 가족컷 200). 각 사진에 "S/A/B" 라벨 + B 사유(눈감음/흔들림/유사컷/기타) 부여
- **인물 클러스터링 검증셋:** 가족 4명이 등장하는 200세트 (각 세트 30~50장). 각 얼굴에 인물 ID 라벨링
- **응시 검증셋:** 정면 응시 30장 + 비응시 30장
- **데이터셋 보관:** 깃 별도 private 레포 또는 IndexedDB 도구로 관리 (개인정보)

### 12.3 비즈니스 지표 (출시 6개월 목표)

| 지표 | 6개월 목표 | 측정 방법 |
|------|-----------|-----------|

## 15. 용어집

| 용어 | 정의 |
|------|------|
| **B급 사진** | 사용자가 보고 "이건 빼야지" 즉시 판단할 수 있는 명백히 품질 낮은 사진. 진짜 눈감음·심한 흔들림·심한 노이즈·중복 컷 |
| **A급 사진** | 사용자가 "쓸지 말지 망설이는" 컷. 본 도구가 1차 자동 결정 후 사용자에게 토글 권한 부여 |
| **S급 사진** | 사용자가 보자마자 "이거 무조건 쓴다" 결정하는 컷. 본 도구는 이걸 자동 선별의 우선순위로 둠 |
| **유사컷** | 같은 시간대(±5초) + 같은 의상 + 유사 구도(pHash Hamming ≤ N) 사진 묶음 |
| **이벤트 태그** | 폴더 내용의 의미적 분류 (만삭/베이비본/100일/돌 등 §8 참조) |
| **폴더 세션 (FolderSession)** | 폴더 1개에 대한 분석 단위. 폴더당 1개의 세션, 1개의 목표 장수, 1개의 결과 |
| **목표 장수 (targetCount)** | 사용자가 폴더별로 설정하는 최종 선별 장수 |
| **워터마크 ZIP** | 무료 사용자가 받는, 모든 사진에 워터마크가 합성된 ZIP |
| **클린 ZIP** | 결제 후 받는, 워터마크 없는 원본 ZIP |
| **결정 피로 (Decision Fatigue)** | 비슷한 컷 N장 중 어떤 걸 골라야 할지 반복 판단해야 하는 인지 부하 |
| **PersonCluster** | 사진들 사이에서 동일 인물로 묶인 얼굴 그룹. 사용자가 이름 부여 가능 |
| **주인공 (Hero)** | 사용자가 셀렉의 우선순위 기준으로 선택한 인물. 1명 이상 |
| **AND/OR 모드** | 다중 주인공 매칭 방식. AND=모두 등장한 컷만, OR=하나라도 등장한 컷 |
| **비주인공 보장 (Non-Hero Guarantee)** | 주인공이 등장하지 않는 컷(가족 단체컷 등)도 폴더당 N장 보장하는 옵션 |
| **카메라 응시 (Looking at Camera)** | 사진 속 인물의 시선이 카메라를 향함. iris landmark + 얼굴 방향으로 추정 |
